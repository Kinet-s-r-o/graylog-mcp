Web UI documentation

This guide explains every UI section, field, action, expected format, and the equivalent REST examples. The UI itself is protected by a session-based login form.

WebUI URL: http://localhost:8080   MCP HTTP: http://localhost:8081   MCP HTTPS: https://localhost:8443   Admin login: the configured UI_USERNAME and UI_PASSWORD.

1. Graylog Servers

Add a Graylog server, select an existing one, test its API connection, or update its settings. Query execution and newly created agents use the selected server.

Field / action What to enter or expect
Name A local label, for example production or staging.
URL The Graylog base URL, for example https://graylog.example.com. Do not add /api/cluster; the UI adds the API path.
API token Graylog API token. It is sent as Basic Auth in the TOKEN:token format. When editing, leave this blank to keep the stored token.
Verify TLS Choose yes for normal HTTPS certificate verification. Choose no only for a trusted test environment with a self-signed certificate.
Timeout (seconds) Positive connection/request timeout. Start with 30; increase it for a slow or remote Graylog instance.
Test connection Calls Graylog GET /api/cluster using the values currently in the form. It does not save changes.
Add server Saves a new server configuration in SQLite.
Save changes Updates the selected server. Blank API token preserves the existing token.
Existing server Select a saved server to load its editable values. The token is never filled back into the form.

Connection errors: the result identifies the endpoint and provides details for timeout, TCP/DNS/port, TLS, or Graylog HTTP/API errors. Tokens are not included in the displayed URL.

2. MCP Clients / Agents

Each client is restricted to one selected Graylog server and can later be reassigned in the UI. Use the generated key as the Bearer token for MCP or REST agent requests.

Field / action What to enter or expect
Client name A recognizable name, for example grafana-agent or monitoring-agent.
API key (optional) Leave blank to generate a secure key, or provide your own key. The raw key is shown only after creation.
Add client Creates the agent for the currently selected Graylog server. Store the returned key immediately; only its hash and last four characters are retained. 
curl -H "Authorization: Bearer AGENT_API_KEY" http://localhost:8081/mcp

3. Query Rules

How template variables work

${service} is a placeholder, not a built-in Graylog variable and not an automatically detected field. You choose the variable name yourself. In service:${service} AND level:3, the value is inserted before the query is sent to Graylog.

  1. Put a placeholder in the query using ${name}. Use letters, numbers, and underscores; start with a letter or underscore.
  2. Set an optional fallback in Default parameters JSON, for example {"service":"api"}.
  3. Supply or override the value when calling run_saved_query, for example {"service":"web"}. Call-time values take precedence over defaults.

There is no fixed list of variable names. Use descriptive names such as service, host, environment, or status. The direct Graylog query (Lucene) field is sent as-is and does not substitute variables.

Query rules are reusable definitions stored in SQLite. They can be used by MCP agents through run_saved_query.

Field What to enter
Existing rule Select an existing rule to edit. Use New rule to clear the form.
Name Unique rule name, for example errors_by_service.
Description Short explanation shown to agents and administrators.
Type messages returns matching messages; aggregate returns grouped metrics.
Time range (minutes) Positive relative time window, for example 60.
Message limit Maximum messages for message search, for example 100. The server applies its configured maximum.
Time bucket Optional Graylog time unit for aggregation, for example 5m, 1h, or 1d.
Lucene query template Graylog/Lucene query, for example service:${service} AND level:3. Template variables use ${name}.
Group by JSON JSON array of grouping objects, for example [{"field":"service"}]. Use [] for no grouping.
Metrics JSON JSON array of Graylog metrics, for example [{"function":"count"}].
Default parameters JSON JSON object for template defaults, for example {"service":"api"}.
Instructions for the agent Plain-language guidance about when and how the rule should be used.
Save / New / Delete rule Validate and persist, clear for a new rule, or permanently remove the selected rule. 
curl -X POST http://localhost:8081/api/v1/queries/run   -H "Authorization: Bearer AGENT_API_KEY" -H "Content-Type: application/json"   -d '{"name":"errors_by_service","parameters":{"service":"api"}}'

Graylog Metrics JSON reference

Use a JSON array. You can combine multiple metrics in one request. The field must be a numeric or otherwise suitable field from your Graylog messages, except for count. The optional sort value can be asc or desc.

Function Purpose Example
count Counts matching messages. No field is required. [{"function":"count"}]
average Arithmetic average of a numeric field. [{"function":"average","field":"response_ms"}]
latest Latest value of a field in the matching data. [{"function":"latest","field":"status_code"}]
max Highest value of a numeric field. [{"function":"max","field":"response_ms"}]
min Lowest value of a numeric field. [{"function":"min","field":"response_ms"}]
percentile Percentile of a numeric field; configure it in configuration. [{"function":"percentile","field":"response_ms","configuration":{"percentile":95}}]
stdDev Standard deviation of a numeric field. [{"function":"stdDev","field":"response_ms"}]
sum Total of a numeric field. [{"function":"sum","field":"bytes"}]
sumOfSquares Sum of squared values of a numeric field. [{"function":"sumOfSquares","field":"response_ms"}]
variance Variance of a numeric field. [{"function":"variance","field":"response_ms"}]

Combined example

[{"function":"count","id":"requests"},{"function":"average","field":"response_ms","id":"avg_response"},{"function":"percentile","field":"response_ms","configuration":{"percentile":95},"id":"p95_response"},{"function":"max","field":"response_ms","id":"max_response"}]

Metric support and field availability depend on the Graylog version and the fields present in your messages. If a metric fails, verify the function spelling and field type.

4. Run a Graylog query

The first section also provides direct, one-off query controls. Choose Message search, Aggregation, or Managed query.

Message search

Enter a Lucene query, time range, and message limit. Example query: level:3 OR service:api.

Aggregation

Enter a Lucene query, comma-separated grouping fields such as service,source, and metrics JSON such as [{"function":"count"}].

Managed query

Select a saved Query Rule. Its stored query, parameters, grouping, metrics, and limits are used.

Run query sends the request to the selected server. Load streams lists Graylog streams for that server. Results appear in the output panel. 

curl -X POST http://localhost:8081/api/v1/search/messages   -H "Authorization: Bearer AGENT_API_KEY" -H "Content-Type: application/json"   -d '{"query":"level:3 OR service:api","minutes":15,"limit":20}'

curl -X POST http://localhost:8081/api/v1/search/aggregate   -H "Authorization: Bearer AGENT_API_KEY" -H "Content-Type: application/json"   -d '{"query":"*","minutes":60,"group_by":[{"field":"service"}],"metrics":[{"function":"count"}]}'

5. Audit Log

Searches recorded UI/API activity and Graylog calls stored in the SQLite audit database.

Field / action What to enter or expect
Full-text search FTS5 expression. Examples: authentication OR timeout, a phrase such as "connection failed", or a prefix such as error*.
Source Filter by graylog, openai, or mcp; leave All sources to include everything.
Search audit log Runs the search and prints matching records as JSON.
Auto-refresh Automatically reloads the current audit page at the selected interval. Choose Off to disable it. 
curl "http://localhost:8081/api/v1/audit?q=authentication%20OR%20timeout&source=graylog&limit=100"   -H "Authorization: Bearer AGENT_API_KEY"

6. REST and system commands

The REST API is under /api/v1 and is exposed through the Caddy MCP listener. The interactive API reference is available at http://localhost:8081/docs and the OpenAPI schema at http://localhost:8081/openapi.json. 

curl http://localhost:8081/health

curl http://localhost:8081/api/v1/streams   -H "Authorization: Bearer AGENT_API_KEY"

curl http://localhost:8081/api/v1/queries   -H "Authorization: Bearer AGENT_API_KEY"

For Docker, start or rebuild with docker compose up -d --build. The WebUI is at http://localhost:8080/ and MCP is at http://localhost:8081/mcp. For HTTPS use the configured Caddy HTTPS ports (defaults: 443 for WebUI and 8443 for MCP). The internal MCP_PORT and WEBUI_PORT are not published to the host.
